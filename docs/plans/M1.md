# M1 plan: Storage core and shelf skeleton

- **Status:** draft, awaiting review
- **Date:** 2026-10-03
- **Branches:** `m1-core` and `m1-app`, merged into `m1` for the PR (see "Parallel tracks")

## Summary

M1 builds the storage core: the scrap types, a strict frontmatter codec, fingerprints, fractional ranks, an atomic Markdown file store with a folder watcher that ignores its own writes, a SQLite index with FTS5 (and an FTS4 fallback), and launch reconciliation. It also adds the capture pipeline's skeleton: the provider protocol, the registry with its 300 ms budget, the fallback provider, and the privacy filter. On the App side, the shelf becomes a real non-activating panel that lists the Inbox, accepts drops, and supports dragging scraps out. At the end, dropping text from TextEdit writes `Inbox/<date>-<id>.md`, its card appears straight away, and edits made in another editor show up on the shelf.

### M1-R2: frontmatter codec (Core)

The subset (Q2):

| Construct | Read | Written |
| --- | --- | --- |
| `---` delimiters, `key: value` lines | Yes; LF, or CRLF converted to LF in the frontmatter (the body is untouched) | LF |
| Double-quoted strings with `\" \\ \n \t \r \uXXXX` escapes | Yes | Always, for every string value |
| Plain and single-quoted scalars | Yes (Obsidian writes them) | Never; rewritten as double-quoted |
| Integers, `true`/`false` | Yes | Yes |
| ISO 8601 UTC dates (`2026-09-29T14:02:11Z`) | Yes, with or without fractional seconds | Whole seconds |
| The `reference` map, indented two spaces | Yes; the only nested map | Yes |
| `note: \|` block scalar, with the `-`/`+` chomping indicators and an indentation indicator | Yes | `\|`, `\|-` or `\|+` to keep trailing newlines exact; `\|2` when the first line starts with a space |
| Block sequences (`- "a"`) and flow sequences of scalars (`["a", "b"]`, `[]`) | Yes, for `derivedFrom` and unknown keys (Obsidian `tags`) | Block sequences |
| Anchors, aliases, tags (`!!str`), flow maps, folded scalars (`>`), nested maps under unknown keys, several documents | Typed error | Never |

Key order when writing: `schema`, `id`, `kind`, `title`, `pinned`, `board`, `created`, `updated`, `reference` (with `provider`, `app`, `window`, `locator`, `bookmark`, `deepLink`, `label`, `fingerprint`), `asset`, `note`, `noteUpdated`, `derivedFrom`, `aiExcluded`, then unknown keys in their original order. Optional keys with no value are left out, and `derivedFrom` and `aiExcluded` are written only when non-empty or true (Q1).

Files (`Sources/ScrapModel/Frontmatter/`):
- `FrontmatterCodec.swift`: `decode(_ text: String) throws(CodecError) -> Scrap` (the body is everything after the closing `---` line, byte for byte) and `encode(_ scrap: Scrap) -> String`.
- `FrontmatterValue.swift`: `enum FrontmatterValue` (string, integer, bool, date, list, map) and `FrontmatterEntry { key; value }`.
- `YAMLSubsetReader.swift`: a line-based reader that produces entries and line numbers.
- `FrontmatterWriter.swift`: deterministic output and string escaping.
- `CodecError.swift`: `enum CodecError: Error, Equatable` with `missingDelimiter`, `unsupportedSyntax(line: Int, construct: UnsupportedConstruct)`, `invalidValue(key: String, line: Int)`, `missingKey(String)`, `duplicateKey(String, line: Int)`, `newerSchema(Int)`, `invalidUTF8`. A file with a `schema` newer than the app's is an error, so an older app never rewrites a newer file.

Test support: `Sources/ScrapTestSupport/ScrapGenerator.swift`, a seeded generator (`SplitMix64`, so failures reproduce) that builds scraps with emoji, combining marks, CJK and right-to-left text, `:`, `#`, `"`, `\`, tabs, leading and trailing spaces, `---` lines in bodies and notes, multi-line notes with and without trailing newlines, and whole-second dates.

  - `normalizationPassRewritesPlainScalarsAsQuoted()`: a hand-written Obsidian-style file normalizes once and is stable after that.
- `Tests/ScrapModelTests/FrontmatterCodecTests.swift`

  - `writerDoubleQuotesEveryString()`
  - `writerUsesFixedKeyOrder()`
  - `escapesQuotesBackslashesAndControlCharacters()`
  - `noteKeepsLeadingSpacesAndTrailingNewlines()`
  - `unknownKeysSurviveRoundTrip()`: unknown scalar and list keys (`tags`, `aliases`) survive with their order. Covers half of the second criterion; the store half is in R20.
  - `derivedFromAndAIExcludedRoundTrip()`: covers the other half.

### M1-R7: assets (Core)

Files:
- `Sources/ScrapModel/AssetRef.swift`: a path relative to the collection folder (`assets/<shortHex>-<name>`).
- `Sources/ScrapStorage/ScrapDraft.swift`: what `create` takes. It holds the kind, title, body, reference, rank, and an optional `AssetPayload { data; suggestedName }`.
- `ScrapStore.create`: writes the asset atomically first, then the scrap, so a scrap never points at a missing asset. Names are sanitized (no `/`, `:` or leading dot) and get a suffix on collision. Payloads over 20 MB are rejected with `StoreError.assetTooLarge`, which makes the limit a store guarantee.
- `Sources/ScrapCapture/SystemClients/ThumbnailClient.swift`: `protocol ThumbnailClient: Sendable` with `thumbnail(for fileURL: URL, size:) async -> Data?` and `downscaledImage(_ data: Data, maxPixelSize: Int) async -> Data?`. The real implementation (Quick Look and ImageIO) is in the App; Core never touches image APIs.
- The capture pipeline (R12) decides what to store (Q4):
  - Image data on the pasteboard (no file URL) becomes an `image` scrap with the bytes in `assets/`. Over 20 MB, it's downscaled through `ThumbnailClient`. If the item also had a file URL, that original is recorded as the reference's file locator.
  - File URLs become `file` scraps: the path and a base64 bookmark (`URL.bookmarkData()`, not security-scoped) go in the reference, and a thumbnail from `ThumbnailClient` goes in `assets/<shortHex>-thumb.png`. The file itself is never copied.

Tests:

### M1-R8: folder watcher and echo suppression (Core)

Files:
- `Sources/ScrapStorage/FolderWatcher.swift`: an actor whose executor is its own `DispatchSerialQueue`. The FSEvents stream delivers on that same queue, so the C callback gets back into the actor with `assumeIsolated` and no `@unchecked Sendable` is needed. It uses file-level events, 300 ms latency and `WatchRoot`, and provides `events() -> AsyncStream<[FolderEvent]>`.
- `Sources/ScrapStorage/WriteLedger.swift`: a struct mapping a relative path to the content hash and time of the store's own write. `isEcho(path:hash:now:)` matches within 5 seconds. Old entries are pruned whenever the ledger is used, so there's no timer.
- `ScrapStore`: `startWatching()` consumes the watcher. It skips `.trash/`, `.index.sqlite*`, temporary files and `assets/`. Otherwise it hashes the file: a ledger match is dropped; anything else is parsed and emitted as `.updated`, `.problem` or (if the file is gone) `.removed`.
- `changes() -> AsyncStream<LibraryChange>` returns a new stream per caller, so the index follower and tests can each subscribe (see R9).

### M1-R9: index (Core)

Files (`Sources/ScrapStorage/Index/`):
- `SQLiteConnection.swift`: a small non-`Sendable` wrapper (open, `exec`, prepared statements, binding, stepping, typed `IndexError`) owned only by the index actor. `SQLITE_TRANSIENT` is spelled `unsafeBitCast(-1, to: sqlite3_destructor_type.self)`, because the C macro doesn't import.
- `FullTextEngine.swift`: `enum FullTextEngine { case fts5, fts4 }`, detected with `PRAGMA compile_options` (`ENABLE_FTS5`). Tests can force FTS4 through an `internal` initializer parameter.
- `IndexSchema.swift`: the architecture's tables, plus two columns for cards: `preview` (the first 300 characters of the body) and `asset`. The FTS table also gets `body`. `PRAGMA user_version = 1`, WAL mode, `unicode61 remove_diacritics 2`, and prefixes `2 3`. FTS4 uses `tokenize=unicode61 "remove_diacritics=2"` and `prefix="2,3"`.
- `ScrapIndex.swift`: `actor ScrapIndex` with `init(databaseURL:)`. `open() async throws -> OpenResult` returns `.opened` or `.rebuilt(reason)`; it rebuilds when the open fails, `PRAGMA quick_check` isn't `ok`, or `user_version` differs. It also provides `apply(_ change: LibraryChange)`, `search(_ query: SearchQuery) -> [ScrapID]`, `cards(in: CollectionName) -> [ScrapSummary]`, `fileStates() -> [String: FileState]`, `health(of:)`, `setHealth(_:for:)` and `lastRank(in:)`.
- `SearchQuery.swift`: splits user text into tokens, quotes each one (so `"`, `*`, `AND` and `NEAR` are literal), and adds `*` to the last token for prefix search.
- `IndexFollower.swift`: subscribes to `store.changes()`, applies each change to the index, and then republishes it. `LibraryModel` listens to the follower rather than the store, so the UI never shows a change the index hasn't stored yet. This refines the architecture's "the index upserts the row, and `LibraryModel` updates the card".

Unparseable files: the store reports `.problem(path, CodecError)`, the follower logs it (with the path private) and skips it, and nothing writes the file. That's the store half of the fourth criterion.

### M1-R10: launch reconciliation (Core)

Files: `Sources/ScrapStorage/Reconciler.swift`. `Reconciler(store:index:)` and `run() async -> ReconcileReport`. It enumerates `*.md` files outside dot-folders and `assets/`, compares `(path, mtime, size)` with `index.fileStates()`, reads only new or changed files, and removes rows whose files are gone. It writes in batches of 200, one transaction each, with a `Task.yield()` between batches so other index calls get a turn. Every change goes through the same path as watcher changes, so the shelf updates as reconciliation proceeds. The App runs it once, at `.utility` priority, right after the index opens. For two files with the same id, see Q6.

Tests (`Tests/ScrapStorageTests/ReconcilerTests.swift`):

- `skipsDotFoldersAndAssets()`

### M1-R12: providers, registry and coordinator (Core)

Files (`Sources/ScrapCapture/`):
- `ProvenanceProvider.swift`: the protocol from `docs/design.md`, unchanged.
- `ProviderRegistry.swift`: `init(providers: [any ProvenanceProvider], fallback: FallbackProvider)` and `claimant(for:) -> (any ProvenanceProvider)?`, which asks providers in order and returns nil when only the fallback applies.
- `Providers/FallbackProvider.swift`: the locator is `.app`, the label is the app's name (or bundle id), and there's no deep link. `open` activates the app through `WorkspaceClient`. `checkHealth` returns `.unknown`.
- `SystemClients/WorkspaceClient.swift`: `activations() -> AsyncStream<AppIdentity>`, `frontmostApplication() async -> AppIdentity?` and `activate(_:) async -> Bool`. The App's tracker (R14) uses it too.
- `ScrapDraftBuilder.swift`: turns one filtered `PasteboardItemSnapshot` into a `ScrapDraft`. File URL → `file`; a web URL (`public.url`) → `link`, whose body is the URL and whose title comes from `public.url-name` or the host; image data → `image`; text → `text`, whose title is the first line, up to 80 characters. ## Risks and questions

### Risks

- **Panel focus and dismissal (ask first).** Non-activating key panels have uneven keyboard behavior across macOS versions (the architecture's risk table), and "close on a click outside" conflicts with dragging in from another app: the mouse-down that starts the drag happens outside the shelf. S1-1 settles both before R15.
- **FSEvents and Swift 6.** The C callback and `FSEventStreamRef` invite `@unchecked Sendable`. The plan avoids that with an actor on the stream's own serial queue and `assumeIsolated`. If the compiler still objects, I'll stop and ask rather than silence it.
- **`/var` versus `/private/var`.** FSEvents reports resolved paths. Temp folders (and any symlinked library location) have to be resolved before paths are compared, or every event looks external. The tests use a symlinked root on purpose.
- **Atomic replace and FSEvents.** A rename-based write produces events for the temporary file and for the target, and FSEvents may merge flags. The store decides by path filter and content hash, never by flags alone.
- **Echo window.** An external edit that writes exactly the same bytes as the store wrote, within 5 s, is taken as an echo. That's harmless, since the content is identical.
- **Ledger and FSEvents tests use real time.** They wait for events with a deadline instead of sleeping, but they still take about 0.3–1 s each, and CI machines can be slower. The deadlines are generous (5 s).
- **Reconciliation on the index actor.** A 5,000-file first run could hold up other index calls. Batching and `Task.yield()` keep it responsive; if that's not enough, reconciliation can read files on the store actor and send rows in batches.
- **SQLite details.** `SQLITE_TRANSIENT` doesn't import into Swift; user search text has to be quoted for FTS; and FTS4's `remove_diacritics=2` needs SQLite 3.27 or later (the system's is newer). The tests cover each one, on both engines.
- **The YAML subset is stricter than what other tools write.** Anything outside it lands in the logs and is skipped. Q2 widens the subset to what Obsidian writes (plain scalars, single quotes, lists), with fixtures; anything wider would be a separate decision.
- **RTF is AppKit-only on macOS.** `NSAttributedString`'s RTF reader is in AppKit, so the App adds plain text at snapshot time (R18). The same applies to M2-R10's "Foundation's attributed-string readers", so that requirement's text snapshot needs a client protocol too. I'll note it for the M2 plan.
- **Memory with large drops.** A 100 MB TIFF in a snapshot is held briefly. It's released after the capture, and NFR-2 is measured with the shelf closed. If it shows up in the measurements, the snapshotter can skip image data when a file URL is present.
- **Dragging an asset out.** Finder moves files dropped from the same volume unless the source allows only copying. R19 uses an AppKit dragging source with `.copy` only.
- **Linking the package into the App** is the first Xcode build of ScrapKit. Swift 6 warnings that `swift build` doesn't show (or the reverse) may appear.
- **Ask-first items this plan touches:**
  - panel focus (S1-1, R15, R16);
  - the schema 1 file format (Q1, Q2);
  - a background task (reconciliation, once per launch at first shelf open; the architecture already specifies it);
  - observers that run while idle (FSEvents and the workspace notification, both event-driven; the mouse monitors run only while the shelf is open).

  No timers are planned. The ledger expires entries when it's used.

### Questions

1. **Schema 1 keys that `docs/design.md` doesn't spell out.** I propose:
   - `asset: "assets/c71e-floorplan.png"` at the top level, for image files and file thumbnails.
   - For file scraps, `reference.locator` holds the path and a new `reference.bookmark` key holds the base64 bookmark. That keeps one nested map, as R2 requires.
   - `reference.app` holds only the bundle id; the app's name is looked up when it's shown.
   - Absent optional keys are left out, and `derivedFrom` and `aiExcluded` are written only when set.

   That also means file drops need a provider in M1 to own that locator. Should M1 pull forward the Files provider's file-URL claim (path, bookmark, label and `file://` deep link only; `AXDocument`, Quick Look reveal and text snapshots stay in M2-R10)? The alternative is keeping file scraps on the fallback provider with the path in a top-level key, which M2 would then duplicate. I recommend the first option. Either way, this becomes decision 0017 and an update to the scrap-file example in `docs/design.md`.
2. **YAML subset for unknown keys.** Should unknown keys accept plain and single-quoted scalars and lists of scalars (what Obsidian writes), and reject nested maps? I recommend yes. "Tags" in the fourth criterion would then mean YAML tags (`!!str`), not Obsidian's `tags:` list, which must round-trip.
3. **When the provider runs.** R12 says the registry "waits up to 300 ms for the claiming provider, stores the fallback on timeout". The architecture and NFR-5 (card in under 150 ms) say the fallback is saved first and the provider's result replaces it. I propose the architecture's order: save the fallback at once, give the provider 300 ms before marking the capture late, and still apply a late result. Should late results be dropped after a hard cap? I suggest 10 s, to bound in-flight tasks. If you agree, I'll reword R12 to match.
4. **Image files versus image data.** Should a PNG dragged from Finder be a `file` scrap (referenced, with a thumbnail) and only image data without a file become an `image` scrap in `assets/`? I recommend yes. For data over 20 MB, I'd downscale to a 4096 px longest edge, as JPEG (quality 0.9), or PNG when the image has transparency.
5. **Drag-out link for fallback scraps.** A text scrap from TextEdit has no URL to link, so the RTF would show the label without a link.
