### Q3 in detail: the App target's concurrency settings

Xcode's macOS App template set two settings on the App target that change how Swift concurrency behaves. Both live in `project.pbxproj`, so they override the xcconfig files, and `ScrapKit` uses neither.

**`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (SE-0466)** makes every declaration in the module without explicit isolation implicitly `@MainActor`: types, extensions, free functions and globals. UI code then needs no annotations, which is why Apple made it the app template default.

For this project it's a problem:
- **It conflicts with rule 8 and "no blocking work on the main actor".** The real system clients (Apple Events, Accessibility, pasteboard, thumbnails) live in `App/SystemClients/` and must run on the dedicated system-client actor. With this default, a new client type that someone forgets to mark `nonisolated` or make an actor silently runs on the main actor. The compiler doesn't complain, because main-actor isolation is valid. With the normal default the mistake is loud: touching AppKit from non-main code is a compile error.
- **It makes conformances confusing.** A real client in `App/` conforming to a `Sendable` protocol from `ScrapCapture` would be inferred as main-actor isolated. Combined with `InferIsolatedConformances` (below), the conformance becomes main-actor only, so the system-client actor can't use it, or the call hops to the main thread.
- **Non-UI helpers need opt-outs.** `AppInfo` and the loggers would be main-actor isolated, so code on the system-client actor needs `await` or `nonisolated` to read a bundle identifier.
- **`AGENTS.md` lists blanket `@MainActor` as ask-first**, for exactly these reasons.

**`SWIFT_APPROACHABLE_CONCURRENCY = YES`** turns on a group of upcoming language features. Two matter here:
- **`NonisolatedNonsendingByDefault` (SE-0461).** A `nonisolated async` function runs on its caller's actor instead of leaving it. Called from UI code, slow async work then runs on the main actor unless it's marked `@concurrent`. Without the feature, it moves off the main actor by default.
- **`InferIsolatedConformances` (SE-0470).** Described above.

The others are already part of Swift 6 mode or minor. The main issue is that `ScrapKit` doesn't enable these features, so the same `async` function would run on different actors depending on whether it's in `App/` or in the package.

**Options considered:**

| Option | What changes | Cost | Risk |
| --- | --- | --- | --- |
| **A. Remove both (chosen)** | App code behaves like the package: nonisolated by default. `@MainActor` goes on the few AppKit types (`AppDelegate`, `AppEnvironment`, `MenuBarController`, later the panel and board controllers), matching the "main actor" column in `docs/architecture.md`. | About one annotation per UI type. | Low. A missed annotation is a compile error, not a silent main-thread hop. |
| B. Keep both, record a decision | Nothing now. System clients must be explicitly `nonisolated` or actors. | Ongoing reviewer attention. | Rule 8 is enforced only by review. App and package rules differ. |
| C. Remove the main-actor default; turn on the upcoming features in both | Add the same features to `Package.swift` with `swiftSettings`, so both use the newer semantics. | Async code that must leave the caller's actor needs `@concurrent`. | Medium: fewer examples and docs, but likely the future default. Worth its own decision later. |
